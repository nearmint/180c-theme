# Suppression de compte (web)

**Flux** — onglet `/mon-compte/supprimer-mon-compte/` → mot de passe → e-mail à lien unique (24 h) → écran de confirmation → pipeline → déconnexion et notice sur `/mon-compte/?compte-supprime=1`. Aucune route REST. Écrans : `parts/account/deletion-{role,blocked,form,sent,confirm,invalid}.php` ; l'écran découle de l'état serveur, sauf `?confirm=` et `?compte-supprime=`. Le lien d'entrée est en bas de `parts/account/dashboard.php`, à côté de « Se désabonner » et avec la même classe.
**Éligibilité** — rôles tous dans {customer, subscriber} ; aucun abonnement hors {cancelled, expired, switched, trash} ; aucune commande pending/on-hold/processing ; aucune adhésion active **sur un plan « recettes »** (`_180c_recipe_plan_slugs()`, inc/helpers.php). Le plan gratuit `inscrits` octroie une adhésion ACTIVE à CHAQUE compte et ne bloque donc pas, sans quoi aucun compte ne serait jamais supprimable. La suppression, elle, efface TOUTES les adhésions.
**Conservé** — commandes et abonnements terminés, seulement détachés (`customer_id` = 0). Le détachement DOIT précéder `wp_delete_user()`, sinon `WC_Subscriptions_Manager::trash_users_subscriptions()` les détruit définitivement (`delete( true )`, malgré son nom).
**Supprimé** — user + usermeta, favoris (2 tables), jetons de paiement, session WC, adhésions ; commentaires anonymisés ; utilisateur OneSignal supprimé par `external_id`.
**Newsletters** — retrait SYSTÉMATIQUE, en mode **archive** : `DELETE /lists/{id}/members/{hash}`. Jamais `delete-permanent`, qui rendrait l'adresse définitivement non réinscriptible. L'archive coupe les campagnes et laisse la personne libre de se réabonner ou de recréer un compte. Échec = non bloquant, tracé, `newsletter_removed` = 0.
**Non traité** (audit 2026-09-01) — `{prefix}login_log` n'a ni `user_id` ni e-mail, `{prefix}180c_consent_log` n'a pas de `user_id` : rien n'y relie une ligne à un compte.
**Tables** — `{prefix}180c_account_deletions` (journal anonyme, aucun identifiant). Colonnes `reason` et `reason_text` **réservées** : le formulaire ne pose plus de question, elles sont écrites vides et conservées pour éviter une migration si un motif redevient pertinent.
**Constantes** — `_180C_CONTACT_EMAIL` (repli `woocommerce_email_from_address`), `_180C_ONESIGNAL_APP_ID` / `_180C_ONESIGNAL_REST_KEY` (module Notifications).
**Piège** — `delete-permanent` (non utilisé ici) fait refuser par Mailchimp toute réinscription de l'adresse ; `inc/rest/newsletter.php:1567` répondrait alors « Cette adresse ne peut pas être réinscrite. Veuillez nous contacter. » (HTTP 422). C'est précisément ce que le mode archive évite.
**Mise en place** — 1) créer la table `{prefix}180c_account_deletions` (colonnes : voir `log.php`) ; 2) Réglages > Permaliens > Enregistrer ; 3) `_180C_CONTACT_EMAIL` en `wp-config.php` ; 4) purge du cache page.
